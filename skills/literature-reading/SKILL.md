# literature reading

服务于这样的阅读习惯：用户先看 AI 总结，再自行浏览论文图表；Codex 继续完成逐图复述和中英对照全文，供用户回来细读。总结与复述使用简体中文，保留必要的英文术语。

## 内容边界：只总结和复述文章

- 所有阶段仅以当前文章的正文、图表、图注及已取得的本篇附录/补充材料为内容来源。只呈现其中明确写出或标注的信息，以及作者明确表达的解释、观点和结论。
- 不加入外部知识、其他文献的内容、常识性背景、术语科普、类比、阅读建议或个人思考。文中提到的背景与他篇研究可按作者原有表述复述，不另行查阅并扩写。
- 不根据文章内容自行推导结果、补全因果链、解释机制、建立图间关系或延伸应用。即使某判断看起来合理、明显或能由数据计算得到，只要作者没有明确表达，就不写入输出。保留原有数值，不自行计算差值、比例、效应量或推算图中读数。
- 不评价创新程度、证据强弱、研究质量、实验设计优劣、局限、适用边界或“该图不能证明什么”。这些内容只有在作者明确讨论时，才以作者观点复述，不追加自己的判断。
- 原文未涉及的信息直接省略，不增设“文中未报告”“作者未讨论”“还需要验证”等条目，也不为填满固定栏目而补写。原文含糊之处保留其含糊程度，不用推测替作者消除歧义。
- 忠实保留作者观点的归属和语气，包括假设、推测、不确定性及作者自行作出的推论。可使用“作者认为/提出/报告”等表述，不把作者推测强化为确定事实。
- 阅读材料中的总结、图解与译文只包含上述文章内容，以及必要的章节标题、页码、图号和对照标识。文件链接、材料无法读取、识别不清或任务尚未完成等必要执行状态在聊天中简短说明；不可避免的缺文标记仅用于定位，不写成对文章的评论。

## 执行节奏与范围

- 默认连续完成「总结 → 逐图分析（仅复述） → 中英对照全文」。完成总结后立即保存为 `summary.html` 并在聊天中提供链接，再继续后两阶段；逐图复述完成后提供 `figures.html`，全文对照完成后提供 `bilingual.html`。聊天可同时呈现简短总结。不要等全部译完才给总结，也不要在阶段之间要求用户回复“继续”或确认已看完图。
- 用户明确只要某阶段、只读某些章节、改变顺序或指定格式时，按该次要求执行，不强制扩展为全流程。复用已有总结或图解时，核对论文版本，并依据上述内容边界删除其中的外部内容或自行判断。
- 在当前任务中持续推进，不声称后台任务已启动或会在用户离开后继续，除非实际存在这样的执行机制。
- 优先使用用户提供的 PDF、附件或全文链接。只有摘要时可以先给标明范围的摘要总结；全文或图像不可获得的部分，明确说明并请求相应材料，不虚构后续图解或全文翻译。
- 一次处理多篇时，分别组织每篇的来源、总结、图解和译文；篇数多到影响交付顺序时，再澄清优先级。

## 读取与定位原文

1. 从原材料确认论文标题、作者、年份、已有的 DOI 或链接以及所用版本，不为补充背景检索其他来源。可取得同一篇文章的全文。读取全文结构、主要方法、结果、讨论及图注后形成总结，不将只读摘要的结果表述成全文结论。
2. 建立简明覆盖清单：章节、方法所在位置、图号及子图、表格、附录和已提供的补充材料。清单供后续防漏，不必向用户倾倒提取过程。
3. PDF 文本提取与页面图像结合使用。检查双栏顺序、跨页段落、连字、脚注及公式。扫描件可先 OCR；可疑数字、符号和图中标签回到页面核对。
4. 给重要结论与每幅图提供可回查位置，如“PDF 第 7 页，Fig. 3b”。印刷页码与 PDF 页序不同时，说明使用哪一种页码。
5. 补充材料只有在实际取得且属于本篇文章时才能纳入复述与翻译；未取得的材料在聊天中说明。文中对他篇文献的引述保留原有归属，不自行核验、补充或改写成新的论据。

## 第一阶段：中文总结

先交付一份忠实于作者表述的中文总结，长度随论文复杂度调整。以下项目仅在文章明确涉及时呈现：

- **研究问题和背景缺口**：复述作者提出的问题、背景与研究动机。
- **研究设计与方法**：研究对象、数据或样本、关键实验或模型、主要对照及评价方式。
- **主要结果**：围绕核心发现组织；关键定量结论保留数值、单位、条件与原文位置，不拼凑脱离条件的数字。
- **作者提出的贡献与意义**：仅复述作者自己的表述。
- **作者讨论的局限与适用边界**：仅复述作者明确指出的内容。
- **图文对应**：按原文图号列出正文或图注明确对应的研究内容，不自行推荐阅读优先级或重建论证关系。

每项总结均应能定位到原文表述。作者只报告相关性、提出机制假设或使用不确定措辞时，保留原有表达，不加强、不纠正、不评价其结论。

## 第二阶段：逐图与子图复述

**先实际查看原图，再与图注、正文和相关方法核对。** 查看图像是为了准确复述图中标注的信息，不是自行发现趋势或推导结论。若工具无法显示或图像分辨率不足，在聊天中说明受限的图号或子图；仍可复述可读图注与正文已经写明的内容，但不能声称已经看清原图。

按原文图号逐一复述所有已取得的正文图及其子图，包含图形摘要和独立示意图；已提供的补充图单列并保留原编号。对表格复述原有变量、数值与作者已写明的结果，不自行归纳新结论；完整内容仍纳入对照版。

每幅图仅呈现原图标注、图注及相关正文明确提供的以下信息；未涉及的项目省略：

1. **作者说明的目的**：复述作者对该图或相关实验目的的表述。
2. **图中要素**：转述分组、对照、处理、颜色、符号、坐标轴、单位、刻度与图例；显微图中的通道、标记物、比例尺和定量方式；示意图中的节点、箭头及作者给出的含义。只描述已标注或已定义的内容，不另加通用读图教程。
3. **逐子图复述**：使用 Fig. 2a、2b 等原标签，分别转述作者报告的实验、结果与解释，不能用一句总括替代全部面板。若作者未对某面板文字解释，只转述其可读标注和相关图注，不从图形走势或图像形态自行提炼发现。
4. **原文统计信息**：保留作者给出的 n、重复类型、误差线定义、统计检验、比较对象、数值及显著性符号含义。只复述已经定义的内容，不猜测符号、不重新计算或评价统计结果。
5. **作者的结论与说明**：复述作者明确与该图关联的结论、解释或局限。与其他图的联系只有在作者明说时才复述，不自行添加机制、逻辑衔接或“这说明”的推论。

尽可能在图解 HTML 中内嵌清晰的原图或完整裁图，保留标签与图例，并注明来源页码。图片采用 data URI 等离线内嵌方式，不作为单独的图片文件交付。不要重绘、补画或美化原始数据。文件大小或工具受限时，可用精确页码与图号定位，在聊天中说明没有嵌入原图。

## 第三阶段：中英对照全文

目标是可供逐段精读的完整译文，不能以中文摘要、意译大纲或图解冒充全文翻译。

### 对齐与完整性

- 默认纳入标题、摘要、正文各节、方法（包括位于文末的方法）、结论、图题图注、表格及表注、脚注、致谢、声明和已提供的附录/补充材料。参考文献保留原始书目信息及编号，默认不逐条翻译；任何未纳入部分均在聊天中说明。
- 保留原章节次序和段落层级，按“英文原文 → 中文译文”一一配对。默认以段落为单位，不把多个原段合并成一个概括译文。长段落只有在对应关系清楚时才拆分。
- 为段落设置稳定标识，并记录来源章节或 PDF 页码；跨页段落可标页码范围。图号、表号、公式号及文内引文保持一致，方便在图解、译文和原论文间回查。
- 修复明显的排版断词、重复页眉页脚与提取顺序错误；不得借“修复”改写英文论述。无法可靠辨认的片段保留定位并标记“原文识别不清”，不要自行补全。
- 表格保留行列对应、数值、单位及注释，可在同一单元格中保留英文并附中文。图注完整对照，不能只翻译图题。图内英文标签必要时另列对应译名，原图保持原样。

### 翻译忠实度

- 准确保留否定、比较方向、条件、时态所表达的研究事实和 may/suggest 等不确定程度；不把“提示”升级为“证明”。
- 保持专业术语一致；关键术语首次出现采用“中文（English，缩写）”，后续使用一致译法，缩写仅在原文给出时保留。若整理术语表，只列原文出现的词语与对应中文译名，不添加文章未给出的定义或背景。
- 保留基因/蛋白命名、化合物名、模型名、缩写、数字、单位、上下标、希腊字母、公式及引用关系。公式中的符号不擅自汉化，公式后解释可译。
- 不添加译者的阅读提示、背景补充、疑点、评述或推导，即使单独标为“译注”也不加入。原文作者自己的注释正常翻译并保留归属。

### 对照布局

中英对照全文使用与总结、逐图复述相同的 HTML 样式规范。桌面宽屏为左英文、右中文的同段对照；每一对段落使用一个 `.parallel-row`，其内分别为 `.parallel-cell[lang="en"]` 与 `.parallel-cell[lang="zh-CN"]`，窄屏同段先英文后中文。不得将整篇英文与整篇中文各放在一个独立长栏，以免段落失去对应。保留章节目录、段落锚点和图号定位。

公式采用可离线显示的方式；复杂公式无法可靠排版时，内嵌带编号的原图或保留可读公式文本，不以排版结果掩盖识别错误。

## 全部交付文件使用统一 HTML 排版

- 总结、逐图复述、中英对照全文及额外生成的阅读材料均交付为 UTF-8 `.html`，不自动降级或另行交付 Markdown、Word、PDF、纯文本、独立 CSS、图片或脚本。内部提取与检查的临时文件留在工作目录；原始论文是输入，不受此交付格式限制。只有用户后续明确要求改变格式时才调整。
- 每个 HTML 都是能独立离线打开的完整文档，具有 `<!doctype html>`、`<html lang="zh-CN">`、UTF-8 字符集及 viewport 设置。CSS、图片和必要的公式资源内嵌，不依赖 CDN、网络字体或另一个文件；若实际环境受限，说明具体限制，不偷偷换格式。
- 生成任一文件前读取 [assets/reading.css](assets/reading.css)，将其原样内嵌到 `<style data-literature-reading>` 中。三个阶段使用完全相同的这份 CSS，不各自设计样式，不通过额外样式表、内联 `style` 或脚本覆盖排版。若同次阅读中用户指定排版修改，在任务工作目录建立这一 CSS 的统一副本，修改该副本并同步内嵌到全部文件，包括已交付的阶段文件；不因此修改已安装的 skill 或交付独立 CSS。
- 页面内容置于 `<main class="reading-document">`。总结和逐图复述使用单栏，全文对照使用上述逐段双栏；版式区别仅用于内容组织，不改变同级标题、正文、图注与表格的文字样式。

统一默认值如下；标题字号按语义层级区分，三个文件中的同级元素保持一致：

| 项目                             | 三个文件共同使用的规范                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 字体                             | 全文使用同一字体栈：微软雅黑 → 苹方 → Noto Sans CJK SC → Arial → sans-serif；中英文均不另设字体                  |
| 正文                             | 18px，常规字重，1.8 倍行高，左对齐                                                                               |
| 标题                             | 文档主标题 h1 为 28px，章节 h2 为 24px，子节 h3 为 20px，更深层标题为 18px；均加粗、左对齐、无首行缩进，行高 1.5 |
| 正文段落                         | 首行缩进 2em；段前 0、段后 0.75em；不用空格、全角空格、连续换行或 `<br>` 模拟缩进与段间距                        |
| 标题间距                         | h1 段前 0、段后 24px；h2 段前 32px、段后 16px；h3 及更深层标题段前 24px、段后 12px                               |
| 图注、列表、表格、定位标识与目录 | 字体、18px 字号和 1.8 行高与正文一致；这些结构性元素无首行缩进，不以缩小字体或改变字体区分文件类型               |
| 页面                             | 同一最大内容宽度 1280px，居中；宽屏内边距 40px，窄屏 20px；窄屏只调整布局，不自动改变字号、缩进或行距            |

原图中已有的文字属于原始图像，不重绘以套用字体规范；数学上下标、公式字形保留其必要的语义呈现。除此之外，英文原文和中文译文不采用不同的字号、缩进、对齐或行距。

## 长文与交付检查

- 长论文按章节持续写入文件，维护章节/图表/段落覆盖记录与术语表，避免上下文切换导致漏译或重译。不因单次消息长度限制改成交付摘要，也不将部分译文标为全文完成。
- 若受实际执行限制无法一次完成，交付已完成文件，明确已覆盖章节、尚未完成部分及续接位置；不得暗示后续已经完成。
- 交付前对照覆盖清单核查：各图及子图均已按原文覆盖，没有用自行解释补齐；各原文段落都有对应译文；方法、图注、表格与补充材料无静默遗漏；重点核对数值、单位、否定词、公式编号和引文。
- 逐项检查总结与图解中的实质性表述是否都有文章中的明确出处；删去外部知识、自行计算、推断、评价、阅读建议，以及文章未涉及事项的清单。译文中不得夹入译者观点。
- 抽查英文配对是否仍为原文、中文是否准确；核对重要定量结论与原页面。对 HTML 检查长段落、长表格、公式、内嵌图片、离线打开和窄屏对齐；并排检查三个文件的主标题、章节标题、正文段落、图注和表格，核对它们使用同一 CSS 且没有局部排版覆盖。具备浏览器预览能力时，核对实际计算出的字体、字号、缩进、对齐和行高，避免被浏览器默认样式干扰。不能实际检查的项目如实说明。
- 在用户指定目录或当前环境的交付目录保存三个 HTML：`summary.html`、`figures.html`、`bilingual.html`；多篇论文使用各自子目录，额外阅读材料也为 HTML。最终只链接这些 HTML 阅读文件及说明覆盖/缺失情况，不链接内部中间文件，不重复粘贴整篇译文。
